# LOGI/MONO WATCH

物流業界・製造業界のニュースを自動収集して一覧表示するダッシュボードです。

## 構成

- `server.js` — Express製のバックエンド。複数のRSSフィードを取得・統合・重複除去して `/api/news` で返す
- `public/` — フロントエンド(素のHTML/CSS/JS、フレームワークなし)
- `lib/store.js` — 記事と HubSpot のデータをファイルに保存(Render ではディスク `/var/data`、手元では `data/`。`DATA_DIR` で変更可)。30分ごとに裏で取得し、記事をためていく
- `lib/dedupe.js` — 同じ出来事を報じた別媒体の記事を1つにまとめる(タイトルの似ている度合いで判定)
- `lib/projects.js` — 新設・増設・着工・竣工などの案件記事を見つけ、会社・場所・用途・時期をタイトルから抜き出す
- `lib/comments.js` — チームのコメント(記事ごと・名前つき)をファイルに保存
- 画面は「ニュース」「お客様の動き」「新規開拓候補」「新設・増設案件」「案件地図」「競合の動き」「トレンド」「週報」の8つ
- お気に入り・既読・自分用メモ・設定(ウォッチワード・ミュート・名前)はブラウザ(localStorage)に保存
- HubSpot の会社は、取引の有無・ライフサイクルステージ・担当者で絞り込める。「商談チャンス」は HubSpot の会社が新設・増設の記事に出たもの
- ホーム画面に追加できる(`public/manifest.webmanifest`)。キーボード操作は J / K / Enter / F / C / `/` / `?`

## パスワード

環境変数 `SITE_USER` と `SITE_PASSWORD` の両方を設定すると、サイト全体にパスワード(Basic認証)がかかります。
未設定なら誰でも見られます。ホーム画面に追加するためのファイル(manifest とアイコン。中身はサイト名とロゴだけ)はパスワードなしで取れます。Render 上でパスワードが未設定のときは、チームのコメントは書き込めません(誰でも書き込めてしまうため)。
同じ接続元から15分に20回失敗すると、15分間受け付けません。

## データの取り出し(API)

`/api/news` は期間を指定できます(既定は直近90日)。

- `/api/news?days=7` — 直近7日
- `/api/news?from=2026-10-01&to=2026-10-31` — 日本時間の日付で範囲指定
- `/api/news?days=all` — 保存しているすべて(公開日が2年以内)

## ニュースソースについて

物流ニッポン・LNEWS・物流ウィークリーなどの個別業界紙は、公開RSSの提供が不安定/非公開だったため、
**Googleニュースのキーワード検索RSS**(`news.google.com/rss/search?q=...`)を主軸にしています。
これは特定のキーワードに一致する全メディアの記事を横断的に拾えるため、「業界全般を広く」という要望に合っています。

加えて、公式RSSが確認できた **MONOist**(ものづくり専門メディア／ITmedia運営)を製造業カテゴリに追加しています。

### ソースの追加・編集方法

`server.js` の `FEEDS` 配列にオブジェクトを追加するだけです:

```js
{ url: googleNewsFeed('検索したいキーワード'), category: 'logistics', label: '表示用ラベル' },
```

`category` は `logistics`(物流) / `manufacturing`(製造業) / `topic`(注目トピック) / `thailand`(タイ市場) / `subsidy`(補助金・公募) / `ai`(AI) のいずれかを指定してください。
既存の個別サイトのRSS URLが分かれば、`url` に直接指定することもできます(例: MONOistの行を参照)。

### 関心トピックのタグ付け

`TOPIC_TAGS` 配列で、記事タイトル・本文に含まれるキーワードから自動でタグ(自動倉庫、AMR/AGV、WMS/WCSなど)を
付与しています。ここも自由に編集・追加できます。

## ローカルでの動作確認

```bash
npm install
node server.js
```

ブラウザで `http://localhost:3000` を開いてください。

※ この開発環境(サンドボックス)は外部ネットワークへのアクセスが制限されているため、
Googleニュースやitmedia.co.jpへの実際のフィード取得はここでは確認できていません
(コードの動作・エラーハンドリング・画面表示は動作確認済みです)。
お手元の環境やデプロイ後の本番環境では、通常通りインターネットにアクセスできるため問題なく動作します。

## デプロイ方法(将来の外部公開を見据えて)

Node.js が動くホスティングであればどこでも動作します。おすすめは以下のいずれか:

### Render / Railway(一番手軽)
1. このフォルダをGitHubリポジトリにpush
2. Render.com または Railway.app で「New Web Service」からリポジトリを連携
3. Start Command: `node server.js` / Build Command: `npm install`
4. デプロイ後、自動で発行されるURLでアクセス可能(独自ドメインも設定可)

### Vercel
Vercelは本来Next.js向けですが、Expressアプリも `vercel.json` で対応可能です。
本格的に外部公開するなら、将来的にNext.js構成へ移行するのも選択肢です(その際は改めてご相談ください)。
